# 论文写作 Hub

> [!summary] 使用定位
> 本页是数学建模论文写作的权威操作入口。写作顺序不是从标题一路写到附录，而是先冻结模型、结果和证据，再写正文，最后压缩摘要。具体赛事的官方格式规范高于课程笔记和经验文章。

## 信息采用优先级

1. 当届赛事官方格式、提交和匿名要求；
2. 赛题原文、原始数据和本地可复现结果；
3. 教材、标准、原始论文等可引用来源；
4. 获奖论文拆解和课程经验；
5. 博客、视频笔记等二手写作建议。

## 排版规则分级

| 等级 | 含义 | 执行方式 |
|---|---|---|
| A：官方强制 | 当届全国组委会规范、参赛须知和赛区补充要求 | 无条件执行；不符合可能影响评奖资格 |
| B：项目默认 | 官方未规定时，为保证一致性选定的字体、间距、编号和图表样式 | 全文统一；赛区另有要求时整体替换 |
| C：经验建议 | 博客、课程、获奖论文中的审美或效率建议 | 只在提高可读性且不与 A/B 冲突时采用 |

### 常见冲突裁决

| 争议 | 裁决 |
|---|---|
| 电子版是否包含承诺书和编号专用页 | 不包含；电子版第一页必须是摘要专用页 |
| 字号、字体、行距、颜色是否全国统一 | 官方 2026 规范未统一规定；先使用项目样式，提交前再查赛区要求 |
| 摘要是否必须约 1000 字 | 不是硬规则；只要求标题、摘要和关键词原则上不超过一页 |
| 关键词是 3–5 个还是 4–6 个 | 官方未规定数量；以准确检索主题和一页版面为准 |
| 是否禁止 Word 自带公式 | 官方未禁止；选择一种能稳定导出、可编辑且符号规范的公式工具即可 |
| 文献序号是否必须上标 | 官方只要求正文引用处标注；具体样式按赛区或项目引用样式统一 |
| 正文必须控制在 20–25 页吗 | 这是经验目标；官方上限为正文不超过 30 页 |
| 正文是否可以放目录 | 不可以；官方 2026 规范明确要求正文不要目录 |
| 附录只放“主要程序”是否足够 | 不足；官方要求支撑材料文件列表及全部完整、可运行源程序代码 |

遇到来源冲突时，记录来源和适用年份，不把“看起来更专业”的细节自动升级为官方规则。

## 评阅视角

写完每一章都用四个问题反查：

1. **假设合理性**：哪些结论依赖该假设，依据和失效边界是否写清；
2. **建模创造性**：创新是否服务于题目，而不是为了使用复杂算法；
3. **结果合理性**：答案是否直接响应题问，并有误差、边界或对照支持；
4. **表达清晰度**：评阅者能否在有限时间内找到方法、核心结果和证据。

在此基础上再检查准确、逻辑、简洁、目的性和实用性。标题“尽量简短”只是经验建议；当简短与准确冲突时，优先准确表达研究对象、方法和范围。

## 论文主线：每节都回答一个问题

| 部分 | 必须回答 | 最低交付 | 常见失误 |
|---|---|---|---|
| 标题 | 研究对象和核心方法是什么 | “基于方法/机制的对象问题研究” | 只有口号，没有对象或方法 |
| 摘要 | 做了什么、怎么做、得到什么、如何验证 | 五问均出现方法与关键结果，控制在官方页数内 | 只写背景和方法，不给数值 |
| 问题重述 | 赛题真正要求哪些输出 | 用自己的语言拆分任务、输入和输出 | 大段复制原题 |
| 问题分析 | 为什么选这条模型路线 | 每问一小节，说明信息、难点、方法和依赖 | 提前堆结果或介绍无关理论 |
| 模型假设 | 为何可以这样简化，何时失效 | 必要假设、依据、影响和可放宽方向 | “数据无误差”“误差可忽略”等万能假设 |
| 符号说明 | 读者能否无歧义读公式 | 核心符号、含义、单位和索引范围 | 收录一次性临时变量；符号一词多义 |
| 模型建立 | 题意怎样转成变量、方程和约束 | 目标、约束、递推或机理及其题意解释 | 只介绍通用模型，没有嵌入本题 |
| 模型求解 | 公式怎样变成可复现结果 | 算法步骤、参数、容差、环境和输出 | 只说“用 Python 求解” |
| 结果分析 | 数值意味着什么 | 直接回答题目，解释关键表图与机制 | 只贴表格，不解释 |
| 模型检验 | 结果为什么可信 | 前置检验、残差/误差、稳定性、敏感性或对照 | 只写“结果合理” |
| 评价与改进 | 模型在哪些条件下有效 | 有证据的优点、具体局限、可执行改进 | 自我吹捧或只列空泛优缺点 |
| 参考文献 | 哪些外部知识被使用 | 正文逐处引用，条目格式统一 | 列了但正文不引用；以博客替代原始资料 |
| 附录与支撑材料 | 第三方能否复现 | 文件清单、完整代码、运行说明、复杂证明或大表 | 正文、附录和代码版本不一致 |

标题不能只是“模型建立”“结果分析”的重复。读者只浏览标题时，也应看出“研究对象—方法—结果”的推进关系。每问至少有一个能够直接定位最终答案的结果小节；但不要为了增加层级把一两句话单独拆成标题。

## 摘要装配法

摘要最后写，先建立“五问素材卡”。每问压缩为一到两句：

> 针对【具体任务】，建立/采用【与题意绑定的方法】，得到【核心数值或明确结论】，并通过【最重要的检验】验证。

推荐顺序：

1. 开头用两句话交代研究对象和全文统一路线；背景只保留理解任务所需的信息。
2. 按题号写方法与结果；有明确答案时必须给核心数值、单位和必要精度。
3. 用一句话概括主要验证或模型亮点；只有实际验证过才能写“稳定”“精确”或“可推广”。
4. 选择 4–6 个能够检索论文主题的关键词，以当届格式要求为准。

禁止使用没有证据的“模型较优”“精度很高”“灵敏性较好”。改写为可核验表述，例如“参数变化多少，结果变化多少”“残差上界是多少”“相较哪个基线改善多少”。

## 假设写作与审计

每个假设至少记录四项：

| 假设 | 必要性 | 依据或合理性 | 对结果的影响与失效情形 |
|---|---|---|---|
| 具体、可检验的简化 | 它解决了哪个不可辨识或不可计算的问题 | 题设、数据图形、统计检验、物理常识或文献 | 放松后需要增加什么变量、数据或算法 |

优先保留：

- 题目明确给定的条件；
- 模型结构不可缺少的假设；
- 与本题对象强相关、且能解释影响的简化；
- 能由数据、图形、检验或文献支持的分布和参数假设。

删除或改写：

- 所有论文都能套用的万能句；
- 与后续方程无关的重复假设；
- 把数据和数值误差直接宣布为不存在；
- 为了得到答案而设置、却没有讨论后果的强假设。

## 符号、公式和算法表达

- 符号表只收录跨小节反复使用的核心变量，使用“符号—含义—单位”三列；集合和索引写明范围。
- 符号在正文首次出现时仍需解释，代码变量与论文变量建立一一映射。
- 优化问题按“决策变量—目标函数—约束—约束的题意解释”组织。
- 数值算法至少说明输入、初始化、迭代/搜索规则、停止条件、容差和输出；复杂步骤可配流程图。
- 不大篇幅复述通用算法原理；正文重点写为何适合本题、参数怎样设置、如何实现和得到什么结果。
- 递推、迭代、多组分模型必须统一下标和序号，并使公式、伪代码和程序变量可对应。
- 最终答案在正文醒目标出；超过一页的大表、完整代码和繁长证明移到附录或支撑材料。

## 模型检验选择

检验必须匹配模型，不需要机械地同时做全部项目：

- 几何与递推：距离残差、连续性、单调性、边界构型；
- 数值求根与优化：区间夹逼、收敛、网格/步长变化、双侧扰动；
- 预测与回归：训练外误差、残差诊断、置信区间和基线比较；
- 评价模型：权重稳定性、一致性、排序稳健性；
- 随机与仿真：随机种子、重复次数、区间估计和场景覆盖；
- 开放方案：量化收益、成本、风险和适用边界。

优先展示能直接推翻错误答案的检验，而不是只展示视觉上“好看”的图。

## 图表、引用与附录

- 每张图表都应在正文被引用并回答一个具体问题；图含轴名、单位、图例和数据来源，表含编号、标题和单位。
- 公式使用同一种编辑方式并统一编号，不把公式或三线表以截图形式贴入正文；标题样式、多级编号和交叉引用尽量自动化。
- 数学变量用斜体，常用函数、单位和运算符用正体，向量与矩阵使用统一的粗斜体或粗正体约定；后文引用的独立公式必须编号。
- 简单数据表优先使用无竖线的三线表；表题置于表上，图题置于图下。不要用“上图”“下表”，统一按“图 1”“表 1”交叉引用。
- 图片优先使用矢量格式或足够分辨率的位图；坐标轴名称、单位、图例、线型和关键标注必须在最终 PDF 中清晰可辨。
- 参考文献优先追溯到教材、标准、官方文件和原始论文。网络经验文章可以帮助写作，但通常不应替代模型依据。
- 正文放读者理解论证必需的结果；完整逐时刻输出、详细证明、超大流程图和全部源代码进入附录或支撑材料。
- 支撑材料需提供入口说明、环境、运行命令、输入输出关系和文件清单，并与论文中的数值和图表保持同一版本。

## 交付前五轮检查

1. **答案检查**：五问是否逐一直接作答，摘要、正文、表格和代码结果是否一致。
2. **证据检查**：每个关键数字是否能追溯到脚本、参数、数据和验证。
3. **叙事检查**：假设、符号、公式、算法、结果和检验是否形成闭环。
4. **格式检查**：页数、匿名、标题层级、图表、公式编号、引用、附录和支撑材料是否符合当届规则。
5. **统一性检查**：由一位主笔统一术语和语气，其他成员分别核对数学、代码、图表和引用；确保每一问都有分析、模型、结果和检验。
