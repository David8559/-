# Best Practices

- 原始资料不可被 Cleaner 覆盖。
- 代码、数据、环境与输出共同构成可复现单元。
- 模型结论必须同时记录适用条件、误差和检验。
- Web Clipper 必须绑定 Vault 的精确名称或唯一 ID；目录只填写 Vault 内相对路径。
- Raw、Cleaned、Research 是可追溯生命周期，只有 Research 副本作为主分类笔记参与重复内容判定。
- 综合入门资料先按标题语义确定主分类，再用 Topic 标签表达工具、模型与写作等交叉主题。
- 扫描型竞赛论文先做文本层检测；无文本层时必须结合 OCR 与关键页面视觉复核，公式和数值不能只信 OCR。
- 赛题、数据附件、获奖论文分别采用唯一主分类，用题目总览和项目页建立横向链接。
- 大体积 PDF 使用 Git LFS，避免二进制历史进入普通 Git 对象库。
- 临界问题同时记录高精度数学根和满足题意的安全舍入值；普通四舍五入若改变可行性，必须改用有方向的截断或进位并说明。
- “最短”“最优”等结论必须绑定边界条件；固定切点下成立的条件性结论，不得扩写为允许切点移动时的无条件全局最优。
- 碰撞时刻和速度峰值等连续事件不能只在整数时间表上取值；整数网格用于发现区间，临界值须用连续根搜索或局部极值细化并做双侧扰动验证。
- 模型检验要区分三层证据：约束残差检查方程是否满足，双侧扰动检查临界方向是否正确，网格与尾部检查搜索是否漏解；三者不能互相替代。
- 优先展示会改变答案的失败基线，例如边界单点漏碰撞、普通四舍五入破坏可行性和整数时刻漏尖峰，比只写“误差很小、结果合理”更有说服力。
- 竞赛论文参考文献应在正文完成后按“实际使用的具体句子 → 原始论文或软件正式引用 → 文后条目”建立双向对应，再根据冻结结果装配摘要；写作经验文和未使用资料不为数量而列入。
- 竞赛论文必须同时优化技术质量和评阅可见性：验证图证明“算得对”，解释图帮助读者“先看懂”；抽象的统一模型应先配几何读者层，再给统一公式。详细软件回归可下沉附录，正文优先保留能改变答案的检验和主动约束。
- 集合覆盖、风险和可靠性题先把自然语言写成量词，再写目标函数；对每一次 `max/min`、并集/交集和 `forall/exists` 次序设计一个可区分错误模型的反例测试。
- 多部件协同的消融必须重新计算联合目标。删除边际 $\Delta_i=J(S)-J(S\setminus\{i\})$ 比独立得分更能判断部件是否有实际贡献。
- 启发式优化保留可行解档案和 incumbent guard；代理目标、粗网格与正式目标分层记录，新方案只有在同一严格精度下更优才替换已验证结果。
- 对外比较使用“目标—量词—约束—单位—结果性质”五列表；可行下界、数值上界、解析最优和不同聚合口径不能混排。
